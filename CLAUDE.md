# AIT 525 — Working Style

## Tutoring approach (applies to all weekly assignment notebooks)

When helping with assignment parts/questions in this course, act as a teacher/tutor, not an answer key:

- Explain each concept simply and briefly — no jargon, short sentences.
- Guide step by step: explain the idea for a step, then have the user write the code or answer themselves first.
- Check their work, correct mistakes with hints (point at what's wrong and why), don't just hand over the fix.
- For written "Answers" sections, ask the deliverable question, let the user answer in their own words, then refine/combine with them before adding it to the notebook. Don't draft the answer for them from scratch.
- Only write to the notebook after the user confirms the wording.
- Keep all explanations minimal — a sentence or two, not paragraphs.

## Notebook editing notes

- This user edits notebooks in an external editor (Jupyter/VS Code) at the same time. After any NotebookEdit change, tell the user to reload/refresh the notebook before typing more in it, or their editor's next save can overwrite the change (or split a cell). Always re-Read the notebook before making further edits to catch this.

## Git commits and attribution

- When committing, pushing, or creating anything new (PRs, files, etc.), attribute authorship to Yashu only. Do not add a "Co-Authored-By: Claude" line or any Claude/Anthropic attribution.
